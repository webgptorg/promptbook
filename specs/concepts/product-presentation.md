## One product, two promises

Present Promptbook through two connected principles: an entrusted agenda continues useful authorized work without a person assigning every step, and the owner retains control of the AI that performs it. Roles, goals and rules persist between tasks; autonomy includes waiting and asking for decisions when appropriate.

Explain ownership concretely: the engine runs on the owner's computer or server; project context, agent definitions and tasks are readable, editable files; supported harnesses and models are replaceable execution choices; Git records versioned changes and task traces provide the evidence actually exposed by the tools. Files can be inspected, moved and used by other people or tools without claiming identical behavior in another runtime.

The application and the engine have distinct responsibilities. The engine owns the work and keeps running without an open client. The upcoming commercial application provides convenient remote control through an end-to-end encrypted relay connection. Its intended zero-trust content boundary means the relay is not trusted to decrypt working content. Do not attribute that guarantee to the current [dashboard tunnel](../cli/remote-access.md), or imply that an external model or connected service cannot receive the inputs sent to it by the engine.

## Match the audience

The website presents the complete application, engine and support offering. Its main action collects nonbinding interest; the partner path addresses agencies, freelancers and others deploying for clients. Its quieter installation link leads to localized self-hosting instructions.

The repository README leads with the same purpose, then explains ownership, an illustrative developer agenda, APT, installation and first use. It speaks to people inspecting or running the engine, links to the application and deployment help, and invites a GitHub star and contributions. Do not structure it around internal scheduling machinery. `ptbk about` gives a compact equivalent with the real engine version and public links; detailed operation remains in command help and specifications.

Examples are illustrative scenarios, not invented customer evidence or a promise of unconfigured integrations. The initial examples cover publication and promotion of an AI ta Krajta podcast episode, context-aware CRM follow-up after a customer's new branch, and an overnight software repair with checks and a recorded result. Explain that actual work follows configured access, checks and authority. Do not claim to expose hidden model reasoning, track every external effect in Git or reverse external actions by reverting a commit.

The BUSL-1.1 license remains unchanged. Link to the existing license; this presentation work adds no licensing rights or commercial terms. Discuss local models through supported adapters and task suitability, without promising universal compatibility or a date when model capabilities will improve.
