# Autonomous decisions and genuine attention

[Principle](_index.md) · [Automatic repair](../automatic-repair.md) · [Human interaction](../../cli/user-interactions.md) · [Health](../../cli/health-sub-engine.md)

## Resolve before asking

Use the mandate, effective agent/project instructions, existing evidence, available accounts and ordinary specialist/Fixer consultation. Try useful supported alternatives and cause-aware recovery. A failed attempt, an unfamiliar format, a CAPTCHA or the end of an immediate retry budget does not establish that a human is needed. Avoid repeated equivalent attempts without new evidence and paid idle loops.

Ordinary technical configuration, dependency installation, runtime adjustment and creation of a useful connector/plugin/helper are allowed by default within existing access and authority unless effective instructions restrict them. The operator need not enumerate every such implementation step. Explicit rules, goals, spending limits and review requirements still govern; inability to obtain an OS privilege or an external permission is not permission to assume it.

Content decisions also use available instructions and context first. Ask for an actual missing consequential judgment, information or authority when necessary, rather than repeatedly reconfirming a delegated agenda. A suspicious invoice may need judgment even though the agent is technically able to send the payment. Task purpose is contextual and does not itself grant financial/publication authority or remove a genuine human dependency.

## One attention contract

Active attention/notifications mean **a concrete decision, input or action from the human is now needed**. Apply this to every domain, not only tasks. A significant completed result, unread history, an old failure, a recoverable warning or an ongoing automatic repair is available for inspection without creating attention on that basis alone.

A useful notice identifies affected work, why autonomous resolution is insufficient, what has been tried and the smallest action needed. Missing website secrets/codes use Wallet's protected workflow. Other substantive questions retain their normal attributed conversation. Deduplicate the same unresolved condition and remove stale attention when its condition is verifiably resolved. A saved response clears its answered input immediately; completion still requires verification of the underlying access/action.

Long lack of useful progress must be diagnosed rather than hidden by a live process. When autonomous remedies cannot restore useful work and a human action/decision is necessary, surface one current understandable problem with its impact and attempted remedies. Elapsed time or an exhausted counter alone is not a human question. Unrelated work continues wherever its prerequisites and ownership permit.

## Observe, audit and resume

The operator can always voluntarily inspect work through the existing dashboard. Keep diagnostics and outcomes even when they cause no notification. Git records versioned changes; remote state changes not inherently represented by project files use the existing [Action log](../../cli/action-log.md), including publication of a helper application or an authorized infrastructure resize. Technical intent does not exempt an external effect from audit. Reconcile uncertain effects before retrying them.

Checkpoint the affected operation and resume the correct phase after repair or verified human action, without another generic Start/Retry prompt. Do not turn one waiting credential, task or domain into a global work stop. Actual host exhaustion, deliberate pause/stop and unsafe shared ownership retain their existing lifecycle rules.
