# Expert

[Agents](_index.md) · [System agents](system-agents.md)

Expert understands Promptbook, Book syntax, agents, tasks, project operation and the capabilities of the engine currently running it. Its knowledge must match that engine version and effective runtime context, not a stale project copy or an unrelated global installation.

Expert is never materialized into `agents/.core/`. Updating or selecting another engine may change Expert while preserving the project's own definitions. The engine must make the relevant introspective context available without requiring the user to maintain or copy it into every project. Do not expose credentials as introspection.

Expert's internal Book inherits **Adam from the current project**, then adds the running engine's own expertise. It must not use an isolated universal/internal Adam in place of that project source. Project rules and inherited [common knowledge](../concepts/common-knowledge.md), including external-action impact, therefore reach Expert and descendants such as Teacher. Two projects with differently customized Adams have different effective Experts even with the same engine version. Engine-owned expertise remains version-matched; it does not turn project rules into engine-owned content or gain permission to override them.

Compose and attribute the ordinary inheritance chain: public knowledge referenced by Adam -> project Adam -> engine-internal Expert -> derived project/core agent. No Expert file in `agents/` is required. Apply normal cycle diagnostics, including Adam -> Expert -> Adam, rather than silently substituting an unrelated Adam. Deliberate Void/Null inheritance in a project agent remains an explicit opt-out.

Expert is usable both through `FROM @Expert` and `TEAM ... @Expert`. A project can define `Modified Expert` with `FROM @Expert` and let Teacher inherit that local specialization through `FROM {Modified Expert}`. A programmer can consult Expert without any Expert file existing in the project.

[Initialization](../cli/initialization.md) explicitly assigns the first project-creation task to Expert. [Teacher](core-agents/teacher.md) inherits Expert by default. Expert may internally have a comprehensive Book-like definition embedded in or generated by the engine; no project file or internal encoding is required. Its size is not constrained by the deliberately minimal core-agent boilerplates. This separation lets engine expertise evolve while project agents retain their learning. See [engine/project evolution](../concepts/engine-and-project.md).
