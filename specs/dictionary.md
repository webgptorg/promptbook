# Dictionary

**Message audio:** Recorded speech equivalent to one attributed chat message, bound by `CHAT MESSAGE AUDIO`; text and audio are one utterance, unlike supplemental attachments. Finalized user/agent audio is a versioned project chat asset, with optional shared call timing and honest interrupted/incomplete status. See [audio binding](book-language/commitments/chat-message-audio.md).

**Realtime voice chat:** Full-duplex speech in an ordinary Chat Book, controlled from its local terminal chat through a call-owned browser audio bridge. **Voice capability:** Optional common harness/session operations, initially native Codex/ChatGPT; other adapters explicitly report unsupported. **Media page:** Minimal audio/visualization/caption surface, independent of the project web dashboard/server. **Barge-in:** Interrupting spoken playback, distinct from cancelling underlying work. See [voice behavior](cli/voice-chats.md) and [adapter contract](cli/harness-voice.md).

[Main specification](_main.md)

**Promptbook / ptbk:** One npm package and CLI for operating agents over a project. **Engine version:** The version actually loaded by the service, not latest or the viewer's installation. **promptbookVersion:** Saved initializing/last-migrating engine version in project configuration. **Project migration:** One deterministic mechanism for version-targeted configuration and Book transformations; one coordinator commits the complete applicable pass and version advance, including zero-step upgrades. See [migrations](cli/configuration-migrations.md).

**APT:** Agent–Project–Task, a long-term context convention; the concrete project also includes Chat. **Agenda:** Its continuing responsibility, not the expansion of A. **Project:** Selected directory/workspace in a Git working tree, with managed files/context. See [workspace](cli/workspace.md).

**Agent:** Persistent project-owned role and knowledge. **Core agent:** Ordinary editable required Book: Adam, Router, Tasker, Teacher, Fixer or Chatter, initialized only if missing. **Fixer:** Default-OPEN general problem-solving core, with simple customizable instructions and initial User/Expert team. **Automatic repair:** Foundational cross-system principle using deterministic correction/retry and ordinary Fixer judgment to reduce unnecessary user decisions, not a privileged agent/channel. **Router:** Ordinary core selecting a compatible agent and concrete MODEL, with refinements committed in place. **Tasker:** Ordinary core creating/managing tasks, not performing routing. **MODEL:** Shared agent/task/chat alternatives and filters independent of named tool/account; agent/task requirements intersect. **Chatter:** Default human conversation entry with specialist advice/task creation. **System agent:** Engine-defined reference without project file: Void/Null, User or Expert. See [agents](agents/_index.md) and [automatic repair](concepts/automatic-repair.md).

**Book:** Named Agent, Task or Chat with ordered commitments. **Type-and-name commitment:** Opening AGENT/TASK/CHAT whose content names it. **Reference:** `@Name` for a one-word name or `{Name}` (single braces) for any name; `@Adam` and `{Adam}` are the same reference, and `{{Name}}` is not one. **Name resolution:** Normalize that content and apply deterministic single-winner lookup (built-ins, `agents/`, the rest of the project, Git-ignored content); keywords/filenames are not IDs and shadowed duplicates are diagnosed. **Commitment:** Line-initial uppercase, possibly multiword keyword with common syntax. Configuration naming conventions do not rewrite free-form Book names. See [language](book-language/_index.md).

**Generated task/chat name:** Readable title plus creation date/time and a normalized-distinct discriminator as needed. Preventive [authoring policy](cli/generated-names.md), not mandatory timestamp grammar or permission to rename existing Books. **FROM:** Inheritance. **IMPORT:** Instruction inclusion. **TEAM:** Natural-language consultation relationships, not inheritance/reporting hierarchy; advice can belong to a task or conversation without creating work.

**Task:** Bounded named work with result/completion. **Content work/task:** Work addressing the actual subject/responsibility of this project. **System work/task:** Supporting/service work that enables it; contextual purpose, not a synonym for technical code, core execution or a terminal/instrumental distinction. **TASK PURPOSE:** Optional CONTENT/SYSTEM/UNDEFINED classification, assigned at creation and refined by appended commitments with the last valid value effective. **Core task:** Descriptive work performed exclusively by core agents, independent of purpose, not another execution kind. **Engine-owned task:** An engine-defined operation such as self-update, sharing scheduling/inventory without requiring a project Book/LLM. Earlier narrow uses of system task refer to this ownership, not the broader purpose distinction. See the [purpose knowledge base](concepts/minimal-interruption/work-purpose.md). **Chat:** Persistent attributed exchanges with dynamic agent/user membership, including agent-only/reporting threads. Chat coordinates substantial task work through named source links, live cards, questions and results. CHAT TITLE evolves independently of opening-name identity. **Occurrence/run:** One execution of a task definition, recurring or one-off. **Attempt:** A try/repair within work. **Task origin:** Provenance, not a separate execution mechanism. See [system tasks](cli/system-tasks.md).

**Tool:** Named configured resource in ordered `ptbk.json.tools`, not a fourth Book entity. **type:** Fixed category BROWSER or HARNESS. **variant:** Fixed adapter/implementation enum. **name:** User-editable unique lowercase kebab-case instance identifier. **isEnabled:** Whether the retained instance is available for new selection, default true. Configured, enabled, usable and in-use are distinct. **Retained use:** Original acquired context allowed to finish after an acknowledged saved change, not a frozen whole registry. See [tools](cli/tools.md) and [live use](cli/tool-runtime.md).

**Harness:** Global execution integration with one or more named native/API authentication instances and model capabilities. **Harness adapter/plugin:** Shared typed setup/execution/update contract. **Featured:** Prominent catalog display, not implicit enablement. **Same-variant fallback:** Ordered eligible instances, later used when earlier ones cannot serve work; distinct variants may be chosen for suitability. **Model/thinking level:** Actual provider inference/effort choice, distinct from agent identity, tool instance and saved defaults.

**Browser tool:** Named browser/profile context with coordinated ownership; normal init creates one dedicated managed-global profile choice, and project/personal/custom alternatives or multiple account/site profiles can be configured. Browser website sessions remain independent of harness authentication. Recovery targets the owned named instance, not every browser or the whole engine. **Full browser access:** An agent using a browser tool can do everything a person at that browser could (tabs, any URL, complete page content, trusted mouse/keyboard input, uploads, page JavaScript, DevTools protocol); configuring the tool is the grant, so authority limits actions, never a separate control switch. See [browser](cli/browser.md).

**Environment reference:** `${{ env.NAME }}` in configuration, resolved at runtime, never an inline key or general expression language. **.env audit:** Timestamp/reason comments and preserved historical assignments in the ignored local file, because Git does not retain its edits. Shared/uncertain consumers keep their variables active; disabling a tool does not retire secrets. See [environment safety](cli/environment.md).

**Engine/service:** Owner of scheduling, task/lifecycle state and execution for one concrete project. **Project lock:** Exclusive local owner across installations, not a distributed lock between clones. **Start:** Ongoing supervisor. **Daemon:** Background placement. **Persistence:** Restart/recovery across system restarts, separate from placement.

**Service states:** running permits eligible claims; pausing requests supported interruption/checkpoint of task work and blocks new task claims/continuations; pause stays alive without queued background execution while chat and required routing remain available; stopping drains to exit. Cancelling pending intent returns to running. Force stop is immediate and no hard pause exists. Stopped is observed absence, not a fifth live state. **Waiting for tools:** A running supervisor lacks usable resources, analogous to other legitimate waits; not technical stop/pause. See [lifecycle](cli/service-lifecycle.md).

**Project dashboard/cockpit:** Lightweight live observer/controller, not owner/scheduler. Zero/many clients can attach and closing them does not stop the engine. **Detail panel:** Consistent drill-down into actual execution, named tools/browser diagnostics or enabled sync; main lifecycle controls remain visible. **Global dashboard:** CWD-independent host-wide live table, usable with zero entries, with attachment but no global engine. See [status](cli/status-view.md) and [global overview](cli/global-dashboard.md).

**isAutoSync:** Default-off saved Git synchronization opt-in. **Synchronization:** Periodic/boundary fetch and safe non-fast-forward integration plus publication through existing Git origin/tracking metadata, independent of safe local progress when remote attempts fail. **Synchronization panel:** Dedicated cockpit status/detail/manual-cycle access only when enabled. See [Git synchronization](cli/git-synchronization.md). **Local dashboard connection:** Loopback-only browser/API access on the engine machine, protected against cross-origin and proxy requests.

**Interactive/noninteractive:** Whether terminal input/UI is available or choices are supplied in advance. **Wizard:** Finite setup, not an indefinitely running dashboard. **Check:** Project-defined verification. **Check placeholder:** Explicit successful informational command used for absent initial validation, not proof of tests passing or a startup gate. **Accepted result:** Work satisfying its actual task/validation requirements with truthful persistence, not universal correctness.

**Trace:** Observed evidence in `traces/<task-file-basename>/`, literally the actual source filename without final .book/.md. Declared names/revisions/instances provide provenance, not directory identity. No-task diagnostics are separate. **Human request:** Ordinary actionable attributed agent/User conversation, not a new stored Request entity. **Channel:** Existing terminal/browser/CLI/API interfaces, not an autofix-specific mechanism.

**ptbk.json:** Git-versioned configuration with engine-version evolution, named tools, defaults and explicit temporary overrides. **.ptbk/:** Ignored runtime/ownership/recovery, logs, read markers and selected isolated browser profiles; not wholly disposable. **Host discovery registry:** Protected metadata linking viewers to existing engines across installations, not a project lock, credential store or task queue.

**Wallet:** Per-project login/password-manager sub-engine mediating credentials without exposing them to agents. Encrypted records and recovery metadata stay in ignored project folders; 12 recovery words support transfer and protected host unlock supports unattended reboot. **Browser pool:** Connections from engines to one actual profile process, with no master/slave and closure after last managed disconnect. See [Wallet](cli/wallet.md), [encryption](cli/project-encryption.md) and [browser](cli/browser.md).

**DRY/shared domain logic:** One implementation of tool types, validation, mutations, environment editing and scoped persistence used by init, CLI and dashboard, plus one shared rich-input/paste/asset implementation across init, chat and Book-source editing; frontends differ only in interaction/presentation. See [coding standards](coding-standards/_index.md). **Internal/external context:** Where APT components reside independently of role; [whitepaper](whitepaper.md) separates concepts and long-term directions from current requirements.

**External action / External activity log:** Logical external operation, including meaningful failed attempts, recorded as one Markdown file under `actions/<task-file-basename>/`, independently versioned from optional traces. Pure reads/downloads are excluded; state-changing reads are included and uncertain effects are reconciled before retry. See [external activity log](cli/action-log.md).

**Project brief:** Root `report.book`, `CHAT Report`, Chatter alone appending all briefs. Chatter is the project assistant/coordinator and spokesperson; dashboard/status only read the latest complete message and Discuss creates a new snapshot-seeded thread. **History / Files:** Distinct Git-message/topology and read-only project-inspection pages; Book viewing/editing shares one long-document core. See [report](cli/project-report.md).

**Wallet import:** Protected shared source/selection flow, initially Bitwarden JSON, in optional init and Wallet with individual/all/none selection. **New recovery words:** Preserve/re-encrypt contents when a key remains. **Reset Wallet:** Explicit all-data-loss-confirmed empty encrypted replacement when no key remains; account metadata stays encrypted. See [import](cli/wallet-import.md) and [recovery](cli/wallet-recovery.md).

**Anchor:** User-defined invariant whose meaning agents cannot change themselves. OPEN/CLOSED and learning limits permit evolution of unprotected methods without rewriting the restrictions; the user may deliberately change them. See [anchoring](concepts/anchoring.md).

**Engine self-update:** Low-priority engine-owned system task under project `updates` policy, default on for stable minor/patch within the same major; current prereleases can advance until their stable release without later automatic prerelease re-entry. Shared-global pins constrain every user of that installation. Migration/recovery is part of the operation, not a global control-service scheduler. See [updates](cli/updates.md).

**App version zero:** App-started VPS setup and first project, native lifecycle, attributed plain-text chat, simple Wallet, onboarding files and the automatic-update switch over a zero-trust connection. **Host control service:** Simple project/process registry, launch and monitoring, including stopped-project access; no project scheduling or update decisions. **Unavailable:** A client's inability to verify current state, not proof of stop/crash. See [App integration](app/integration.md).

**Minimal interruption:** Foundational autonomous decision policy: use context, available access and useful technical remedies before asking; active attention requires a concrete needed human decision/input/action. The existing dashboard still permits voluntary inspection and the operator retains final authority. See [principles, analogy and examples](concepts/minimal-interruption/_index.md). **Credential test:** One selected Wallet item's real shared login verification, with protected intervention and latest redacted result retained outside Git; incomplete new entries remain unverified. Wallet-owned TOTP generation/import and mobile SMS retrieval are future capabilities.

**Harness session:** Stable harness execution/conversation context with technical native/engine handles, agent/task/occurrence/chat attribution and retained instructions; distinct from a process, connection, turn or entity Book. A task can use several sessions; chats retain their own contexts. **Harnesses:** Home tile/page replacing Current work/log, including idle sessions and common selected-session detail. **Native attach/detach:** Actual provider client attached to the same session; safe detach restores that detail without terminating the backend. No copied TUI or duplicate executor. **Watch / exclusive / shared:** Enforced read-only viewing, session-scoped exclusive automatic-input gate, or explicitly confirmed ordered dual control. See [sessions](cli/harness-sessions.md).

**Task change:** Chronological TASK CHANGE plus applicable typed commitments, original user/source provenance and scope (`task`, `occurrence`, `future`), retained in the Book. **Saved / Delivered / Applied:** Distinct durable source, target-accepted input and evidenced worker incorporation, per affected session. **Reopen:** TASK REOPEN continues the same work, retaining old DONE/result commits and task identity. **Cancelled:** Unfinished work ended without success. **Retired:** Future recurrence disabled with Book/history preserved. Neither implies deletion or rollback. **Chatter coordination:** Contextual management/delegation through responsible agents; the user need not know task/session inventories. **Active invitation:** `+@Adam`/`+{Adam}` invokes invite/address around the same passive `@Adam`/`{Adam}` reference; examples and replay do not invoke it. See [task control](cli/task-control.md) and [references](book-language/references.md#active-chat-invitation-is-an-action-prefix).

**External-action impact:** Contextual decimal-log estimate of consequence if an action succeeds, evaluated by its executing agent; outcome remains separate. **Logical action:** One intended operation with technical attempts; two actual effects remain two actions. **Inherent batch:** Durable group ID shared by many actions of one bulk operation, distinct from retries and derived task/agent views. **Aggregate impact:** `log10(sum(10^I))`, counting each action once. **Smart priority:** Per-action impact minus one point per 30 elapsed days, then weight aggregation. **Common knowledge:** Public reusable Books at `ptbk.io/book`, independently released from the engine, referenced through project Adam and inherited by internal Expert/Teacher; users may pin, replace or fork them. See [impact](concepts/external-action-impact.md), [log](cli/action-log-ui.md) and [common knowledge](concepts/common-knowledge.md).
