# Dictionary

[Main specification](_main.md)

**Promptbook / ptbk:** One npm package and CLI for operating agents over a project. **Engine version:** The version actually loaded by the service, not latest or the viewer's installation. **promptbookVersion:** Saved initializing/last-migrating engine version in project configuration. **Configuration migration:** An ordered version-targeted transformation; one coordinator commits the complete applicable pass and version advance, including zero-step upgrades. See [migrations](cli/configuration-migrations.md).

**APT:** Agent–Project–Task, a long-term context convention; the concrete project also includes Chat. **Agenda:** Its continuing responsibility, not the expansion of A. **Project:** Selected directory/workspace in a Git working tree, with managed files/context. See [workspace](cli/workspace.md).

**Agent:** Persistent project-owned role and knowledge. **Core agent:** Ordinary editable required Book: Adam, Router, Tasker, Teacher, Fixer or Chatter, initialized only if missing. **Fixer:** Default-OPEN general problem-solving core, with simple customizable instructions and initial User/Expert team. **Automatic repair:** Foundational cross-system principle using deterministic correction/retry and ordinary Fixer judgment to reduce unnecessary user decisions, not a privileged agent/channel. **Router:** Ordinary core selecting a compatible agent and concrete MODEL, with refinements committed in place. **Tasker:** Ordinary core creating/managing tasks, not performing routing. **MODEL:** Shared agent/task/chat alternatives and filters independent of named tool/account; agent/task requirements intersect. **Chatter:** Default human conversation entry with specialist advice/task creation. **Non-agent:** Engine-defined reference without project file: Void/Null, User or Expert. See [agents](agents/_index.md) and [automatic repair](concepts/automatic-repair.md).

**Book:** Named Agent, Task or Chat with ordered commitments. **Type-and-name commitment:** Opening AGENT/TASK/CHAT whose content names it. **Reference:** `@Name` for a one-word name or `{Name}` (single braces) for any name; `@Adam` and `{Adam}` are the same reference, and `{{Name}}` is not one. **Name resolution:** Normalize that content and apply deterministic single-winner lookup (built-ins, `agents/`, the rest of the project, Git-ignored content); keywords/filenames are not IDs and shadowed duplicates are diagnosed. **Commitment:** Line-initial uppercase, possibly multiword keyword with common syntax. Configuration naming conventions do not rewrite free-form Book names. See [language](book-language/_index.md).

**Generated task/chat name:** Readable title plus creation date/time and a normalized-distinct discriminator as needed. Preventive [authoring policy](cli/generated-names.md), not mandatory timestamp grammar or permission to rename existing Books. **FROM:** Inheritance. **IMPORT:** Instruction inclusion. **TEAM:** Natural-language consultation relationships, not inheritance/reporting hierarchy; advice can belong to a task or conversation without creating work.

**Task:** Bounded named work with result/completion. **Chat:** Persistent attributed exchanges for a human/agent or internal agent pair, with optional work/conversation links. **Occurrence:** One recurring execution. **Attempt:** A try/repair within work. **Task origin:** Provenance, not a separate execution mechanism.

**Tool:** Named configured resource in ordered `ptbk.json.tools`, not a fourth Book entity. **type:** Fixed category BROWSER or HARNESS. **variant:** Fixed adapter/implementation enum. **name:** User-editable unique lowercase kebab-case instance identifier. **isEnabled:** Whether the retained instance is available for new selection, default true. Configured, enabled, usable and in-use are distinct. **Retained use:** Original acquired context allowed to finish after an acknowledged saved change, not a frozen whole registry. See [tools](cli/tools.md) and [live use](cli/tool-runtime.md).

**Harness:** Global execution integration with one or more named native/API authentication instances and model capabilities. **Harness adapter/plugin:** Shared typed setup/execution/update contract. **Featured:** Prominent catalog display, not implicit enablement. **Same-variant fallback:** Ordered eligible instances, later used when earlier ones cannot serve work; distinct variants may be chosen for suitability. **Model/thinking level:** Actual provider inference/effort choice, distinct from agent identity, tool instance and saved defaults.

**Browser tool:** Named browser/profile context with coordinated ownership; normal init creates one dedicated managed-global profile choice, and project/personal/custom alternatives or multiple account/site profiles can be configured. Browser website sessions remain independent of harness authentication. Recovery targets the owned named instance, not every browser or the whole engine. **Full browser access:** An agent using a browser tool can do everything a person at that browser could (tabs, any URL, complete page content, trusted mouse/keyboard input, uploads, page JavaScript, DevTools protocol); configuring the tool is the grant, so authority limits actions, never a separate control switch. See [browser](cli/browser.md).

**Environment reference:** `${{ env.NAME }}` in configuration, resolved at runtime, never an inline key or general expression language. **.env audit:** Timestamp/reason comments and preserved historical assignments in the ignored local file, because Git does not retain its edits. Shared/uncertain consumers keep their variables active; disabling a tool does not retire secrets. See [environment safety](cli/environment.md).

**Engine/service:** Owner of scheduling, task/lifecycle state and execution for one concrete project. **Project lock:** Exclusive local owner across installations, not a distributed lock between clones. **Run:** Finite selected queue workflow. **Start:** Ongoing supervisor. **Daemon:** Background placement. **Persistence:** Restart/recovery across system restarts, separate from placement.

**Service states:** running permits eligible claims; pausing drains to pause; pause stays alive without queued background execution while chat and required routing remain available; stopping drains to exit. Cancelling pending intent returns to running. Force stop is immediate and no hard pause exists. Stopped is observed absence, not a fifth live state. **Waiting for tools:** A running supervisor lacks usable resources, analogous to other legitimate waits; not technical stop/pause. See [lifecycle](cli/service-lifecycle.md).

**Project dashboard/cockpit:** Lightweight live observer/controller, not owner/scheduler. Zero/many clients can attach and closing them does not stop the engine. **Detail panel:** Consistent drill-down into actual execution, named tools/browser diagnostics or enabled sync; main lifecycle controls remain visible. **Global dashboard:** CWD-independent host-wide live table, usable with zero entries, with attachment but no global engine. See [status](cli/status-view.md) and [global overview](cli/global-dashboard.md).

**isAutoSync:** Default-off saved Git synchronization opt-in. **Synchronization:** Periodic/boundary fetch and safe non-fast-forward integration plus publication through existing Git origin/tracking metadata, independent of safe local progress when remote attempts fail. **Synchronization panel:** Dedicated cockpit status/detail/manual-cycle access only when enabled. **Remote dashboard access:** Protected HTTP tunnel/pairing, a separate policy from Git autosync. See [Git synchronization](cli/git-synchronization.md) and [remote access](cli/remote-access.md).

**Interactive/noninteractive:** Whether terminal input/UI is available or choices are supplied in advance. **Wizard:** Finite setup, not an indefinitely running dashboard. **Check:** Project-defined verification. **Check placeholder:** Explicit successful informational command used for absent initial validation, not proof of tests passing or a startup gate. **Accepted result:** Work satisfying its actual task/validation requirements with truthful persistence, not universal correctness.

**Trace:** Observed evidence in `traces/<task-file-basename>/`, literally the actual source filename without final .book/.md. Declared names/revisions/instances provide provenance, not directory identity. No-task diagnostics are separate. **Human request:** Ordinary actionable attributed agent/User conversation, not a new stored Request entity. **Channel:** Existing terminal/browser/CLI/API interfaces, not an autofix-specific mechanism.

**ptbk.json:** Git-versioned configuration with engine-version evolution, named tools, defaults and explicit temporary overrides. **.ptbk/:** Ignored runtime/ownership/recovery, logs, read markers and selected isolated browser profiles; not wholly disposable. **Host discovery registry:** Protected metadata linking viewers to existing engines across installations, not a project lock, credential store or task queue.

**DRY/shared domain logic:** One implementation of tool types, validation, mutations, environment editing and scoped persistence used by init, CLI and dashboard; frontends differ only in interaction/presentation. See [coding standards](coding-standards/_index.md). **Internal/external context:** Where APT components reside independently of role; [whitepaper](whitepaper.md) separates concepts and long-term directions from current requirements.
