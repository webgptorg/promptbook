# Rich terminal composer

[Main specification](../_main.md) · [CLI interaction](interactive-ui.md)

Use **one shared implementation** for interactive project intent, task descriptions, planning, chat messages/answers and full-source [Book editing](book-editor.md). Text editing, Ctrl+V paste, clipboard/file acquisition, long-text tokens, attachment storage and readable source serialization are implemented once, not copied into init/chat/Book editors. Apply [Don't Repeat Yourself](../coding-standards/shared-logic.md#one-rich-input-implementation) explicitly. Entry points configure the same editor's submit/newline/save policy rather than build separate input pipelines.

Support multiline text and mixed text/image/document/file input. Preserve comfortable caret editing with arrows, visible focus, keyboard operation and supported pointer interaction without allowing pasted newlines to submit the form. Chat/init are forward flows: Enter submits/accepts the current input, and a discoverable newline action remains available, using Shift+Enter where distinguishable and Ctrl+J as a terminal alternative. Book-source mode uses Enter for newline and Ctrl+S to save without closing. Global navigation never captures focused input.

Represent long pasted text as compact, distinguishable tokens such as `[Pasted text #1, 12,400 characters]`, showing a useful character count and optionally line count. Represent images and other attachments with their kind and identity, for example `[Image #2]` or `[File: brief.md]`. Tokens stand at their insertion positions and refer to the complete payload; they are not summaries. Several pastes and attachments can coexist with surrounding typed text without losing order or association.

Allow inspecting/expanding, editing text and removing individual inserted items before submission. Preserve payloads and drafts across resize, log updates, validation and wizard navigation. Reject unsupported or oversized input explicitly without silently truncating, losing an image or submitting partial content. No model call is needed to compose or retain the input.

Ctrl+V invokes the shared rich-paste logic for text, images and documents wherever the platform/terminal exposes the payload, with discoverable file attachment/path selection as a fallback. Do not pretend clipboard access exists on unsupported terminals or remote hosts. Plain/noninteractive input accepts equivalent text and explicit file references without depending on interactive clipboard state.

Collapsed display must never become persisted content. [Initialization](initialization.md) expands full text into `specs/_initial.md`, copies accepted attachments into the project and emits relative links. Other authoring workflows preserve equivalent payloads in their own source context. Accepted chat messages expand their full text/attachments into the selected `chats/*.book` document and a separate Git commit by default, not only a transient runtime request. Do not lose drafts or commit merely on entering the chat view. Do not replace readable source with a proprietary composer dump.

Design references reviewed for this contract are the official [Codex CLI documentation](https://learn.chatgpt.com/docs/codex/cli), [Claude Code terminal configuration](https://code.claude.com/docs/en/terminal-config) and [Claude Code interactive mode](https://code.claude.com/docs/en/interactive-mode). Reuse the interaction principles, not provider-specific shortcuts, exact collapse thresholds or internal cache layouts.
