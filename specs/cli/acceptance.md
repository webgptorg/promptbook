# Acceptance scenarios

[Main specification](../_main.md)

These are verifiable product outcomes, not an implementation plan or evidence of completed tests. Exercise common behavior with local fixture projects and deterministic substitutes; paid provider checks are separate and explicit. Topic specifications add focused acceptance outcomes. Unless explicitly testing an exception, use automatic commits; [uncommitted workflows](git-persistence.md#explicit-uncommitted-workflows) are tested separately. Configuration/tool identifiers follow their [naming contract](../coding-standards/naming.md), independently of free-form Book names.

## Installation and startup

- **S01:** Global `ptbk` and project-local `npx ptbk` work outside this repository. Two projects use different versions, and their daemons and Experts use the correct installation after restart.
- **S02:** Successful init saves technical setup, the original initial specification and one ordinary Expert task, then automatically starts the background agenda. It does not execute Expert inside the initializer, create an Expert project file or add a duplicate generic starter. Repeating satisfied initialization preserves source, creates no empty commit or duplicate task, and reuses an existing service without resetting it.
- **S03:** Plain start creates one daemon with persistence and a free loopback HTTP port, attempts the default protected remote tunnel, renders one status snapshot and exits without attaching a dashboard. With remote access ready, the primary URL/pairing QR works from another network; a failed tunnel is visibly degraded rather than a false localhost mobile-access claim. No-server/no-tunnel/no-QR and an explicit port behave as advertised; a port conflict is not reported as success. Bare `ptbk` shows help/version without starting or prompting.
- **S04:** Start/pause/resume/stop/restart/status/show target the correct project and report once, distinguishing an accepted pending request from completion. Repeated/concurrent starts do not duplicate it, attach a dashboard, cancel deliberate pause/stop intent or control an unrelated PID. Status/show never start work; an intentional completed stop remains stopped after reboot until an authorized start, including a subsequent explicit init's start operation.
- **S05:** Verify daemon reboot/crash recovery on Linux, macOS and Windows. No-persist disables automatic restart but retains state. `start --raw` remains a one-shot daemon launch; `start --foreground --raw` stays foreground with plain events. Explicit foreground execution never silently becomes a daemon; unsupported persistence prerequisites are reported.
- **S06:** Successful init begins eligible work automatically without a separate start, setup prompt, manual assignment, open dashboard or Run action. A later plain start reuses that service. After intentional stop, explicit start resumes processing. Assigned work executes, unassigned work runs Manager then its target, and due discovery produces useful tasks when prerequisites exist. Later missing tools keep the engine running with a resource wait rather than requiring a restart or another setup wizard.
- **S07:** The official **Check ptbk** workflow passes on Node 22/24 across Linux, macOS and Windows for the accepted source. An authorized **Publish ptbk** release validates its exact tag through that matrix, publishes and verifies the package, and finishes successfully. Both workflows must pass for release acceptance; a failed required platform job or skipped publication is unsuccessful. Failed validation blocks publication and remains visible; code/test fixes use a new immutable release tag. See [GitHub Actions checks and publication](releasing.md).

## Initialization, configuration and maintenance

- **I01:** With dependencies available and no update selected, intent is the first input. Blank intent, an empty destination and usable selected browser/harness tools produce a useful skeleton, preserved blank `specs/_initial.md` and one ordinary Expert readiness task. No check-command question appears; absent real validation receives the explicitly labelled informational placeholder, which does not block start or claim tests passed. Setup installs the running version locally, saves its `promptbookVersion` and commits without model work; the daemon executes bootstrap normally. Repeating satisfied setup is a file no-op, including after task completion/archiving.
- **I02:** Existing files, Git history/current branch, staging, customized agents/settings and a declared devDependency survive init. Reinitialization reuses recorded intent without reauthoring the project's purpose. Partial setup/new required roles receive only missing support; required configuration evolution uses its separate migration pass. Unrelated changes never enter setup commits, and original specifications/assets and real checks are not overwritten. A newly created repository uses main; an existing branch is preserved.
- **I03:** Start over genuinely missing structural setup offers the same initializer for the selected folder and rechecks readiness. Initialized projects bypass it, including those waiting for deliberately disabled/missing tools. One handoff creates one service without recursive init/start. Raw/noninteractive use never launches hidden setup/login prompts and identifies genuinely missing decisions/prerequisites.
- **I04:** Creating a child inside Git offers back, an ignored independent repository or a real submodule. Back changes neither project; ignored-child and submodule metadata are correct and repeatable. Child commits and parent changes stay separate; no invented remote, accidental parent commit or unrelated index changes occur.
- **I05:** Both global invocations and parent-local invocations creating a child offer destination-local dependencies by default. They install the exact running version, not latest. Existing local dependencies/devDependencies are preserved; selecting global does not silently add a local copy or claim a parent-local executable is global.
- **I06:** An outdated invoked engine offers an early optional self-update after intent, defaulting to yes. No keeps the current version only when compatible with the saved project version. Yes updates the correct installation and exits before setup with a rerun instruction and recoverable intent/assets. Offline lookup and failure are honest; unattended use never silently accepts an update. A known newer project configuration still requires the compatibility gate, and rerun does not require repasting the draft.
- **I07:** Defaults, legacy environment fallbacks, project settings and explicit overrides resolve in documented order, preserving false/empty values and path bases. Temporary flags/controls do not rewrite defaults; explicit saved tool management does commit its own changes. Secrets and runtime state never enter JSON. Trace and init-to-service settings use the same precedence, canonical naming and live-refresh rules.
- **I08:** A catalog of hundreds initially shows only featured names and More, with all integrations reachable. Selecting one configures only that integration; an authenticated global installation is reused. Supported/installed but unconfigured or disabled tools are not implicit routing/update candidates. Init, runtime, CLI and dashboard use the same typed tool/plugin contracts, not separate implementations.
- **I09:** One outdated selected harness offers yes/no; several offer keep, update all outdated selected, or choose individually. Current/unselected harnesses are untouched. Start automatically maintains enabled harnesses by default, honors disabling overrides and avoids updating an active shared invocation. Several account instances sharing an executable do not cause duplicate competing updates. Failure preserves a usable compatible version or visibly blocks only affected work.
- **I10:** Select two initial harness integrations, one healthy and one needing login/setup. Init verifies both selected integrations and the initial browser, unless the user explicitly removes a selection; an opened login window is not completion. The placeholder check is accepted without a check setup question or validation-deferral blocker. Cancelled essential login, unresolved dependencies or failed local setup commit is incomplete. Failed remote publication does not block otherwise ready local launch. Failed service launch preserves saved setup and queued work; resume reuses completed steps.
- **I11:** The first task is assigned to Expert and links to the original specification from its actual task-source location. It adapts project content, agents, checks and follow-ups without replacing original input. Ordinary execution/traces/completion/result commits apply. A placeholder is not real verification evidence; genuinely configured failing checks cannot be stamped passed or replaced with a fake success. Init does not run project checks or claim they passed; existing validation and tasks remain intact.
- **I12:** A native globally installed Codex reporting `Logged in using ChatGPT` is ready without another login, API key, `--allow-credits` or model probe, even without credit-control flags. Native execution/TEAM/planning retain that context and ambient keys do not override it. An explicitly configured API_KEY tool is a distinct authorized route/fallback with a symbolic key reference. Quota/credit failures remain real outcomes; no unconfigured paid fallback, fabricated provider control or shared-login overwrite is permitted.
- **I13:** Launch a project with a healthy globally installed Codex on a custom/version-manager PATH and native login store. Resume its saved worker under an OS-manager environment lacking those locations: it still detects that same account without a login or model probe. Missing-harness and recovery blockers remain labeled throughout recheck delays, even after their action request is answered. Actual cause, next action and recheck are visible in terminal/browser/API; Skip wait cannot bypass them. Older saved workers retain the pinned Node global bin fallback.
- **I14:** A genuine User clarification starts one named agent-authored chat linked to its waiting task, ends the provider turn promptly and checkpoints without retries or another model call. Restart preserves the exact chat/question and task context. Independent work runs only after safe ownership release and when lifecycle permits new claims. One real committed reply resumes without replaying effects; finite run reports incomplete while waiting.
- **I15:** Compose arbitrary intent with prose, long pasted blocks and several images/files. Compact tokens can be inspected/edited/removed without accidental submission; resize/back navigation preserves the draft. `specs/_initial.md` retains original text exactly and ordered relative attachment links, without summaries, placeholders or temporary-machine paths. Save it with the ordinary Expert task before dispatch, including customized source paths.
- **I16:** The Traces screen saves explicit `traces.isCommitted`, `traces.isVideoIgnored` and `traces.isVideoRecordingEnabled`. Defaults are local-only traces, ignored videos and enabled recording. Effective parent/video exclusion is visible; resume reuses answers. Noninteractive equivalents preserve false and never prompt invisibly for missing decisions.
- **I17:** Init creates a missing editable `agents/.core/chatter.book` with `AGENT Chatter` and TEAM access to all other initialized core/specialist roles, without self-consultation. Reinit preserves customized Chatter/team and older core Books. Upgrades add only missing required roles; invalid/colliding definitions use repair rather than replacement. See [Chatter acceptance](../agents/chatter.md#acceptance-outcomes).

## Agents, language and assignment

- **A01:** `@Adam` and `{{Adam}}` are identical; existing `{Adam}` is a readable compatibility alias. Case/diacritics/separators are normalized for agents/tasks/chats. One shared resolver orders built-ins, nonignored common folders shallow-first (agents/tasks/chats root order), other nonignored Books and eligible ignored Books such as node_modules. First matching named Book wins; collisions are shadowed/diagnosed, not merged or intrinsically fatal. Typed references require the winning kind; hidden/dependency Books are referenceable without automatic discovery/edit authority. See [reference acceptance](../book-language/references.md#acceptance-outcomes).
- **A02:** Default inheritance reaches Adam; custom ancestors are allowed when the chain terminates. FROM cycles fail. Void/Null/0 ends inheritance and is a TEAM no-op; User fails in FROM and creates a request in TEAM; Expert works in both.
- **A03:** Reciprocal TEAM relationships are valid, consultations are bounded and at most one project task executes. Advisors receive their own instructions and cannot exceed task/conversation authority. Conversation-only advice neither invents a task nor bypasses the queue for actual specialist execution.
- **A04:** Before every task and during waits, discover current enabled tools, global harness executables, authentication/models and browser readiness. Missing resources in an initialized project produce a running resource wait, not automatic reinitialization or service exit. Otherwise actionable unassigned work creates one checked Manager prerequisite with a direct authorized bootstrap and visible relation, without recursive assignment. Explicit requirements/paid restrictions and retry deduplication remain intact.
- **A05:** Implicit/explicit OPEN produces one Teacher follow-up; limited OPEN is respected. CLOSED prevents learning, including pending learning work. Teacher is customizable but must be CLOSED, and non-agents are not rewritten as local Books.
- **A06:** Canonical Books begin with AGENT, TASK or CHAT and their name content, using one grammar/parser. Standalone Books need no folder hint and moving one does not change kind. Multiline content/fenced control-looking examples survive. Documented commitments/aliases retain meaning; malformed controls do not activate work. Task GOAL is bounded assignment, not an agent's ongoing discovery goal.
- **A07:** Verify full multiword uppercase keywords, numeric/reference content and the three-letter minimum: standalone A/I/AI in prose is not a commitment. Unknown full keywords are not shortened into known prefixes. TASK AGENT/CHAT MESSAGE are not roots; missing/empty/repeated/unsupported roots are diagnosed. Legacy plain-name/ENTITY sources are explicitly converted preserving identity, not silently rewritten during discovery. See [syntax acceptance](../book-language/syntax.md#acceptance-outcomes).

## Tasks and persistence

- **T01:** Agent/Task/Chat identity is normalized opening-name content, not generated ID or filename; kind does not create separate name namespaces. First-wins duplicate lookup selects one without merging; Fixer diagnoses shadowing. Moving preserves identity; declared rename requires link/history reconciliation. Routing/relationships use the selected name, while source-filename trace storage remains separate.
- **T02:** Each accepted task/occurrence has one result commit containing accepted/check-generated changes, TASK DONE, follow-ups, task-internal conversation and eligible traces/video. Subject is `PTBK: <task name>`, with assignment and `Task-Name`, not Task-ID. Creation, assignment, repair and later integration remain separately scoped operations with provenance.
- **T03:** Run is finite with selected execution constraints; start is indefinite. Neither freezes the live tool inventory for the entire task/session. At most one task executes across interfaces; future high-priority work does not block ready work or trigger premature goal enquiry.
- **T04:** With no unfinished present/future work and no active cooldown, a running engine with usable resources performs ordinary goal enquiry automatically. Useful tasks execute without another command; enquiry can create future work or no work. Cooldowns survive restart; unavailable goals/supporting agents/empty results do not busy-loop. Pausing/pause/stopping prohibit new discovery, assignment and follow-up claims as well as ordinary claims.
- **T05:** Earliest-start boundaries, explicit offsets and ambiguous local times are respected. Recurrence preserves anchors, identity/history, coalesces downtime, never overlaps and executes at most once per finite invocation.
- **T06:** Interrupt during work, checks, conversation, completion, commit or push. Resume the correct safe phase without duplicate execution/messages/commits, preserving revisions, names, traces, staging, hooks/signing and external effects.
- **T07:** Commit/push failure does not rerun successful model work. Reconcile reverts/changed dependencies with effect evidence. Worktree integration preserves the original result commit and intervening project commits using a visible non-fast-forward merge, or keeps unintegrated work recoverable. No rebase/amend/force reset replaces history to make integration succeed.
- **T08:** Legacy Markdown states/priorities/sections/selectors remain supported. Old ptbk-task-id comments are historical non-authoritative metadata and not generated. Conversion preserves named work, assets, meaning, timestamps and provenance without two runnable copies.
- **T09:** Add normally commits one unfinished typed/date-decorated task with bounded GOAL before dispatch, enabling Manager/start without manual Git. Other authorized versioned changes commit by operation. Human-facing messages commit separately, task-internal TEAM with the result. Read/no-op creates no commit; unrelated edits remain protected.
- **T10:** Ordinary `--no-commit` init/add/run/start visibly preserves uncommitted work without invented SHAs or rerunning accepted effects, and propagates through init's service only. It conflicts with isolation/autosync and cannot silently disable mandatory configuration-migration or explicit tool-management commits: incompatible requests fail before those writes. Owned writes do not require ignoring unrelated dirt. Reentering default mode reconciles safely rather than creating a surprise aggregate commit.
- **T11:** New task/chat generators include readable date/time before collision: add/chat/plans/bootstrap/assignment/discovery/learning/repair/follow-ups/consultations. Repeated text, fixed clocks, batches and concurrent writers still produce distinct normalized names and paths without shadowing another kind. Links use final names. See [generated-name acceptance](generated-names.md#acceptance-outcomes).
- **T12:** Undated/differently dated existing names remain ordinary valid text. Parser never requires/extracts a name timestamp. Conversion, pending-save retry, recovery and recurrence retain existing name/history. Filenames are separate date-leading storage; moves do not change logical identity/kind.

## Controls, access and evidence

- **U01:** Terminal, foreground, browser and direct API show/control one engine with actual version. Shared lifecycle, settings, tool management and replies propagate, while startup-only/deferred choices are labelled. Closing attached viewers does not stop the engine; explicit shared stop does.
- **U02:** Agent-issued TEAM User requests and human-action needs use ordinary attributed chats, not a new persistent Request entity or Fixer channel. A durable answer is accepted once through existing interfaces; `ptbk answer` remains a compatibility reply even without HTTP. Direct management confirmations use the shared operation's input policy, not hidden noninteractive prompts.
- **U03:** New projects create one named browser defaulting to the dedicated OS-user-global Promptbook profile, not personal Chrome. Project/personal/custom alternatives remain available and independent of headless mode. Additional named browsers can represent separate site/accounts, preserving sessions and safe shared-profile ownership. Reinit retains existing choices.
- **U04:** Browser website sessions and harness native/API authentication are independent. No password/key/session data enters Git, ordinary status or traces, including sensitive video frames. External content is not authority to change policy; localhost/opaque public hostname does not bypass authorization.
- **U05:** Read-only operations work offline without mutation, initialization, updates, normalization/migrations, tunnel startup or paid calls. Plan does not implement/delegate writes, fix does not consume backlog, and verify remains human review.
- **U06:** Logs/usage/status describe observed outcomes with unknown/truncation explicit. Teacher uses actual evidence. Low disk, unavailable login/quota and repeat failures retain work and a controllable daemon. Optional capture failure does not unnecessarily halt safe work.
- **U07:** Init is finite with Step X of Y, Expert guide and brief celebration after confirmed local setup/start, no dashboard opening or bootstrap wait. Remote failure is a separate honest pending outcome. Dashboard is indefinite; chat is persistent conversation and add finite model-free authoring. Rich input/navigation/resize preserve drafts.
- **U08:** Bare/help/about, wizard and dashboard show actual invoked/running versions, not installed latest or another client's version. Narrow/raw help remains scoped/readable without provider dumps or setup effects.
- **U09:** Failures explain actual phase/effect/next action, redacted evidence and versions. Trace-storage failure does not invent saved files. Commit/push failures never rerun already successful model work.
- **U10:** Predefined choices use keyboard selectors, including browser sources, harnesses, traces, sync opt-in/provider/visibility and applicable confirmations. Enter selects focused default and Esc cancels. New chat remains Chatter-first; alternatives include valid hidden/core/Expert, not User/Void/Null. Free-form chat uses the rich composer; secret entry remains concealed.
- **U11:** Cockpit panels distinguish attention, work, main lifecycle controls, tools, enabled sync, queue, activity/results and connection. Execution/tool/browser/sync details use discoverable collapsed navigation, not hidden lifecycle actions. Narrow/raw/reduced-motion modes retain truthful names/state/actions and priority. Raw output has no decorative QR or secret disclosure. See [layout](dashboard-layout.md) and [visual acceptance](../agents/visual-identity.md#acceptance-outcomes).
- **U12:** Dashboard attaches without a second worker. Q/Ctrl+C leave client only; C starts Chatter-first chat, A opens the highest-priority existing request, all-chats exposes others. Direct chat uses the same picker and Ctrl+C closes it only. Disconnect does not lose messages or release engine ownership.
- **U13:** Lightweight SPA consumes authenticated API for state, tool management, enabled synchronization and durable chats, without server-rendered runtime HTML. Revision/idempotency rules prevent duplicate actions/messages across clients. Refresh/tunnel failure never creates work or stops the daemon. No frontend duplicates domain logic.
- **U14:** Bare/help/--help show top-level scope; init/start/dashboard/add/tool and aliases/nested subcommands support equivalent scoped help. Pretty/raw keep relevant defaults/examples without unrelated dumps. Help is offline, requires no service or command inputs and never executes the operation. Errors identify the correct scope. Document pause/resume, separate stop --force/-F, tool --force and last-type confirmation, global dashboard and autosync in their proper scopes.
- **U15:** Scan default protected pairing QR outside the local network, authenticate and inspect/answer the same project. Bare public URL has no project authority. Pairing is short-lived/single-use, locally renewable and revocable. Read-only status does not mint/rotate credentials. Secrets stay out of ordinary API, logs, redirected output and Git; cross-origin/stale/reused requests fail safely.
- **U16:** No-tunnel contacts no provider while keeping local HTTP; no-server disables both and conflicts with explicit tunnel. No-QR/raw do not change exposure. Repeated start/clients create no extra worker/tunnel. Remote tunnel outage is degraded without unnecessary local blocking or unprotected fallback. Stop/restart/run completion manage owned tunnel; changed URLs invalidate stale ready claims. See [remote acceptance](remote-access.md#acceptance-outcomes).
- **U17:** Execution details show actual agent, named harness instance/variant, model and thinking level with overrides and separate attempt/consultation contexts. Unknown/default/unsupported data is distinguished, not guessed. Task changes clear stale activity; raw/browser/API agree. Opening/closing detail does not mutate state.
- **U18:** For each named browser/profile source, inspect effective path/mode/ownership/health. Inject failure and observe bounded automatic recovery without a viewer, then manual recheck/retry/restart via the same engine operations. Safe-boundary deferrals are visible. Preserve sessions, active evidence and unrelated browsers; do not restart the engine. Important blockers remain visible with details closed.

- **C02:** A read-only status chat need not create a task; another chat can create several tasks. Directed M:N LINKs between chats/tasks preserve final names and navigate incoming/outgoing relations correctly.
- **C03:** An agent-originated question creates a named waiting-for-user chat and attributed notification, distinct from unread-only. A opens its full conversation; one committed reply resumes linked work once when permitted. Chatter never replaces existing author/participant and other chats remain browsable.
- **C04:** Each accepted human-facing User/agent message has a scoped PTBK chat commit with Chat-Name. Task-internal agent consultations are recorded in Chat Books and commit with the task result. Viewing alone does not commit.
- **C05:** One ordered Book resolver normalizes case/accents/separators; built-ins then nonignored common shallow-first, other nonignored and eligible ignored sources. Exact spelling has no priority. Duplicates shadow, not merge; Fixer may repair or consult under its normal policy. Tool-name collision rules do not change this existing Book lookup behavior.
- **C06:** Fixer is an ordinary required minimal OPEN core with initial TEAM User and Expert. Learning uses normal Teacher evidence. Custom all/some/no-User consultation, including removing User, survives upgrades; Expert alone refreshes with engine version. No special Fixer channel/worker is introduced.
- **C07:** Reopen/append/reconnect/recover a chat without refreshing its name date, adding another CHAT root or damaging literal control-looking text. Existing undated names remain valid; message timestamps and name content are distinct.
- **C08:** Chatter specialist advice is bounded, attributed and linked to the original conversation without inventing a task or changing its participants. ## Service lifecycle and exclusive ownership

- **L01:** CLI, terminals, browser and API observe exactly running, pausing, pause, stopping as live states. Running can wait for tools/tasks/sync; blockers/phases are separate. Exited is observed absence, not fifth live state. Force stop is immediate; no hard-pause operation exists.
- **L02:** Pause prevents next claim, lets current work settle once and remains alive. Graceful stop uses the same drain then cleanup/exit, covering checks, pending commit and safe human-wait checkpoints. No implicit force or routine human reply is required merely to checkpoint shutdown. Pause without current work is immediate.
- **L03:** Resume cancels pending pause/stop without replay. Changing pausing to stopping or stopping to pausing preserves current work; cancelling shutdown for pause is confirmed. Noninteractive choices are explicit, repeated requests idempotent, stale confirmations cannot overwrite newer intent, and cancellation after irreversible shutdown reports too late.
- **L04:** From pause, resume work, stop orderly or restart into one replacement. Force stop while idle still performs quick orderly cleanup. All clients invoke the same operations, including cancellation/intent changes, and immediately see the same state.
- **L05:** `ptbk stop --force`/`-F` terminates only selected owned execution without false task completion or deleting tools. Owner cleanup is bounded/best-effort; external uncatchable kill has no cleanup guarantee/new lock-removal requirement. Viewer signals close only viewer. Never kill unrelated processes or remove a replacement owner's lock.
- **L06:** Restart drains visibly, releases old owner and launches one replacement with the same project/effective installation and placement, without overlap. Cancelling pending restart cancels replacement start. Lost replies/start failure/unconfirmed stop are truthful; no blind replay targets a successor. Completed deliberate stop suppresses persistence, while cancelled stop does not leave permanent stop intent.
- **L07:** Concurrent starts across global/local versions and equivalent paths produce one project owner. Several dashboards share state, but none acquires/releases the lock; closing all leaves engine active. Pause still excludes another owner. Preserve recovery/session/evidence during controlled cleanup.

- **G02:** Global/local installations and versions all appear in accessible host discovery. Actual path/version/process/mode/lifecycle/work/freshness update across exits. No CWD-derived project or global worker is invented.
- **G03:** Select a row to attach without cd, worker creation or lock acquisition. Return/close without stopping. A vanished/replaced/unreachable/incompatible owner is diagnosed rather than accidentally controlling another process.
- **G04:** Verify empty versus failed/permission-limited discovery, stale records/reused PIDs, long paths, resizing/raw/foreground/no-HTTP/offline use. Do not bypass OS permissions/expose credentials/delete locks from stale registry entries. Stable selection never jumps to another live engine. ## Unattended operation and audit trails

- **O01:** On an awake supported host with usable tools and an authorized recurring AI-news publishing agenda, simulate a month without dashboard/operator. Work and follow-ups continue without routine per-post approval; results and task-linked evidence remain inspectable. Respect pauses, schedules, target accounts and scope; do not invent activity during legitimate idle.
- **O02:** Inject network/provider failure, restart and hidden harness prompts. Recover/classify within bounded budgets without duplicate external effects or paid idle loops. Deterministic corrections precede ordinary Fixer judgment; genuine missing authority/login/unsafe ownership uses current agent consultation policy. Safe independent work continues when possible. An alive avoidably stalled service fails this scenario.
- **E01:** Each canonical task has `traces/<task-file-basename>/` copied literally from its source filename without final .book, not normalized TASK name or generated ID. Test different declaration/path, preserved date/case/characters and custom source locations. Available output/events retain attempts/occurrences/names/revisions/chats/Git without fabricated private reasoning.
- **E02:** Follow task/Git history to actual harness output and playable browser video in either display mode. Attribute each named tool/account/attempt and label gaps; exclude authentication data and unrelated desktop/project activity. Unsupported/failed capture is honest.
- **E03:** Exercise all trace-commit/video-ignore/recording combinations. Whole-tree exclusion wins, recording independent. Eligible finalized evidence shares the task result; excluded data remains local and is not force-added. `.ptbk/`, profiles and `.env` remain excluded. Preference changes preserve history/evidence and unrelated ignore rules.
- **E04:** Interrupt capture/result persistence and recover without mixed attempts, self-SHA commit loops or duplicated effects. Retention/truncation protects pending-work evidence; storage failure reports actual diagnostics, not fictional paths.
- **E05:** Rename declaration and filename independently: logical identity follows the former, new trace location the latter. Preserve verified old evidence without occupied-destination merging/re-execution. Legacy .md sections have distinct attributed records under the literal filename. Basename conflicts/ambiguous old traces are diagnosed, not resolved by opaque hashes or lost evidence. See [trace acceptance](traces.md#acceptance-outcomes).

## Configuration migration, tools and synchronization

- **M01:** Compare numeric major/minor/patch and prereleases, including 9 versus 10 and prerelease versus stable, without lexicographic mistakes. Equal versions create no version commit; an older engine offers update without project downgrade. Missing `promptbookVersion` always implies the fixed documented legacy baseline, with no age/shape analysis or immediate Fixer invocation merely for absence.
- **M02:** Apply exactly the ordered migration targets between saved/running versions, allowing gaps and zero steps. Coordinator alone stamps the final engine version. One isolated commit records the entire pass, even a version-only change, with no tasks/unrelated staged content. Repeated loading is a no-op. Failure/crash/signing rejection preserves original/prepared recoverable state without partial success, duplicate tools/commits or replayed work.
- **M03:** First conversion preserves all existing harness options/enabled states and browser profile/executable/sessions while producing canonical named tools and symbolic secret references. Preserve unrelated config and real checks. Migrate known boolean/enum spellings without losing false. Autosync defaults off even with an origin; migration itself does not install tools, log in, publish or run tasks. Existing conflicting new/legacy fields go to repair, not silent overwrite.
- **M04:** Canonical JSON keys/boolean prefixes, user kebab identifiers and uppercase fixed enums round-trip. Unambiguous mistakes correct once with a scoped commit and preserved references. Unknown variants or post-normalization collisions use ordinary Fixer and do not silently redirect accounts. Read-only inspection never saves corrections. Free-form Book names, provider IDs, environment names and paths are not renamed as configuration identifiers.
- **P01:** Configure multiple browser profiles for separate sites/accounts and dedicated plus explicitly allowed personal use. Appropriate authorized fallback works without pretending two records sharing one profile are different identities or publishing/paying from the wrong account.
- **P02:** Choose different harness variants for suitability while both are healthy. Within one variant, use the first eligible usable instance and fall back in list order only when needed. Exercise two isolated native contexts, subscription-to-explicit-API and ordered company/second-company/personal API accounts. No ambient key authorization, global-login overwrite, cross-instance leakage or replayed effects occurs; earlier recovered instances regain future priority.
- **P03:** Resolve only `${{ env.NAME }}` from declared process environment/.env precedence, without arbitrary expression execution. Missing keys make the instance unavailable. New/rotated/retired `.env` lines retain history and timestamp/reason comments; secret values never enter Git, diagnostics, shell arguments or API output. A shared, disabled-tool, script or uncertain consumer keeps the variable active. Disable never retires credentials.
- **P04:** Init, CLI and dashboard use the same management types/operations, with equivalent validation, canonicalization, environment edits and commits.
