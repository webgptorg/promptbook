# Interruption, ownership and recovery

[Main specification](../_main.md) · [Unattended operation](autonomous-operation.md) · [Project locking](locking.md)

Only one engine may own task execution/mutations for a project at a time, regardless of installation/version. Many clients may observe/control that owner; they are not additional task writers. Coordinate related worktrees/nested projects sharing Git. Verify process records: neither a reused PID nor an old timestamp proves ownership. Owner-only cleanup, including internal force stop versus external hard kill, follows [locking](locking.md); recovery does not grant viewers permission to unlink another process's lock.

Retain enough local `.ptbk/` information to distinguish unfinished work, checked results, created commits, pending synchronization, unanswered chat messages and external effects. Link records through declared normalized task names and actual source paths/revisions to evidence in **`traces/<task-file-basename>/`**, where the component is the literal source filename without `.book`/`.md`. Preserve previous names, paths and older name-derived evidence through verified reconciliation. Do not recompute current evidence paths from TASK names. Restart reconciles state, traces, actual files and Git before continuing; do not discard uncertainty or reset prior attempts to empty.

Start resumes a provably safe unfinished phase without repeating accepted work. A failed commit resumes persistence; a failed push resumes synchronization. Investigate ambiguous edits/effects from available evidence first. Continue an attributed agent→User chat only when safe resolution remains unavailable, while supervisor/controls stay available. Safely checkpointed task-local blockers need not prevent independent work; unresolved shared ownership can block the project and must be explained.

[Pause/stop draining](service-lifecycle.md) prevents new task claims while allowing current work to settle or reach a safe recoverable checkpoint. Cancelling a pending request does not replay its active task. Internal force stop preserves available interrupted-work evidence without recording false completion. External uncatchable termination has no guaranteed cleanup; this does not introduce a new next-start lock-deletion requirement.

`ptbk recover <task-reference>` inspects without mutation. Explicit `--action resume|retry|acknowledge` selects safe continuation, deliberate retry or acceptance of a failed outcome; `--occurrence` disambiguates recurrence and `--dry-run` previews. Acknowledgement is not success. All actions share ownership/revision checks with automatic recovery. Routine recoverable failure must not require the manual command.

Never kill unrelated processes, seize a live profile, overwrite user edits or repeat an external action solely for a clean state. Browser repair uses its coordinated [recovery controls](browser.md); a Git revert does not undo browser effects. Retain their task-linked evidence. See [process modes](process-modes.md), [persistence](persistence.md), [user interactions](user-interactions.md), [traces](traces.md) and [Git persistence](git-persistence.md).
