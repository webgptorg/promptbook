# Saving project and task changes

[Main specification](../_main.md) · [Automatic Git persistence](git-persistence.md)

`ptbk add` creates a task through its finite wizard or supplied description/stdin/template and priority inputs, without a model call or executing the task. Confirmation saves the task and commits the operation by default. Preserve the supplied description, write a canonical `TASK <name>` opening commitment, and put descriptive work under GOAL rather than an unprefixed name or free-standing introduction. Form the final name from a readable title plus creation date/time using [generated-name policy](generated-names.md), including normalized collision checks. Leave the task unfinished and report its actual final reference/path and resulting commit, not merely that a file was written.

A successful default add must leave its new task source ready for the existing agenda, including automatic Router assignment when routing is omitted. It must not routinely cause 'Router cannot change or assign an uncommitted task source'. That protection remains valid for unrelated manual edits; the remedy is correct authoring persistence, not removing the ownership guard.

The same default applies when saving approved plan proposals, creating templates, editing task metadata, archiving/reviewing results, migrating, repairing project support or explicitly saving runtime settings to versioned configuration. Commit one logical operation with `PTBK: <summary>`. Temporary settings, read/unread chat markers and other ignored-state-only changes need no Git commit; **creating chats and appending each independent human-facing message or answer do**. Task-internal agent consultations remain inside the parent task commit. Read-only/dry-run paths remain read-only.

All generators of new runnable task/chat entities use the same name policy, including approved batches and work saved through another client. A template is not yet an independently runnable task; allocating a new task from it receives a new final name rather than reusing a template identity. Editing, converting, replying to or recovering an existing entity preserves its name and does not append another timestamp. Automatic naming adds neither a new authoring mode nor an extra routine confirmation step.

Validate destinations and preview freshness before writes. Coordinate with the running project's task/Git ownership: a save waiting for a safe boundary is visibly pending, not completed. Recheck normalized-name and destination-path collisions at publication, without changing another Book. Only release a newly authored source for dispatch after its authoring commit succeeds. Preserve other tasks, user edits and the index; do not commit another active task's work to make add succeed. Source or commit failure retains the prepared name and recoverable data, identifies the failed phase and never silently duplicates a task on retry.

Cancelling before confirmation changes nothing. `--no-commit` explicitly saves without committing, reports the resulting uncommitted paths and explains the consequences for ordinary start; it never pretends this opt-out is the clean ready-to-run workflow. Authoring approval authorizes only that operation's content, not arbitrary project writes or push.

Acceptance includes interactive and noninteractive add, several tasks saved as one approved batch, add during a running task, default Router assignment afterwards, cancelled input, commit failure and intentional no-commit. Include repeated descriptions, a fixed clock and concurrent creation; names must be distinct after normalization while retries retain their prepared entity. All surfaces must agree on whether a save is pending, committed or explicitly uncommitted.

Full-source [Book editor](book-editor.md) saves preserve user content even when diagnostics warn about a mistake; warnings do not disable Save. Schedule detected issues as ordinary Fixer repair without claiming the source is safe to execute. Share revision checks, asset persistence and scoped Git operations with other authoring entry points.
